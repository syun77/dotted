# Dotted Training Studio 開発見積もり

## 1. 概算

`Dotted Training Studioプログラム設計.md`および`ドット絵スキル向上ツール仕様.md`と、現時点では実装コードがないことを前提にすると、Phase 1の製品MVPは次の規模を見込む。

- 工数：**6.5〜9人月**
- 開発費：**約520万〜1,080万円（税別）**
- 経験者1名での期間：**7〜10か月**
- 2名体制での期間：**4〜6か月**

費用は1人月20人日、開発単価80万〜120万円として算出している。正式見積もりでは、担当者のRust／egui経験、UIデザイン品質、Windows／macOS両方の実機QA、配布方法を確定する必要がある。

## 2. Phase 1の工数内訳

| 作業 | 工数 |
| --- | ---: |
| Cargo workspace基盤、技術検証、CI | 0.5〜0.75人月 |
| ピクセル編集コア、Undo／Redo | 1.0〜1.25人月 |
| egui編集画面、入力、1×プレビュー | 1.25〜1.75人月 |
| 模写→記憶描き→比較→振り返り | 1.0〜1.25人月 |
| `.dotted`保存、復旧、SQLite履歴 | 1.0〜1.5人月 |
| 診断、比較、PNG出力 | 0.75〜1.0人月 |
| QA、両OS対応、改善、最終リファクタリング | 1.0〜1.5人月 |
| **合計** | **6.5〜9.0人月** |

この範囲には、仕様で定義された次のMVP要素を含む。

- Pencil、Eraser、Fill、Eyedropper、Undo／Redo
- 整数座標での編集、Nearest Neighbor表示、常時1×プレビュー
- 2〜8色パレット、使用色数表示、上限超過警告
- 参照画像、観察メモ、模写、独立した白紙からの記憶描き
- シルエット、グレースケール、背景、反転の非破壊診断
- 模写と記憶描きの横並び／点滅比較、3項目の振り返り
- `.dotted`形式、復旧自動保存、SQLite履歴索引、未完了再開
- 原寸および整数倍PNG出力
- Windows／macOS向けの基本的な動作確認

## 3. 体制別の目安

| 進め方 | 期間・費用の目安 |
| --- | --- |
| 経験者1名でPhase 1を開発 | 7〜10か月、520万〜1,080万円相当 |
| 2名体制でPhase 1を開発 | 4〜6か月。工数は大きく減らず、連携コストが加わる場合がある |
| 仮説検証用の縮小版 | 2〜3か月、2〜3人月 |
| 開発会社へ一括外注 | 管理・デザイン費込みで約800万〜1,500万円を想定 |

縮小版では、Pencil／Eraser、Undo、1×プレビュー、模写→白紙記憶描き、比較、簡易保存に絞る。正式な`.dotted`コンテナ、SQLite履歴、高度な復旧、全診断、配布品質の両OS対応は後段へ回す。

## 5. 開発費に含まない費用

このアプリはローカル完結設計のため、完成後のAI API費や常設サーバー費は基本的に発生しない。ただし、次の費用は別途必要になる可能性がある。

- 5〜10人の初心者ユーザーテストに伴う募集・謝礼
- Windows／macOSの検証機材
- Apple Developer Program、コード署名証明書
- 配布サイト、更新配信、クラッシュレポート等の運用基盤
- リリース後の問い合わせ対応、保守、追加OS対応

これらには、初年度で**10万〜50万円程度**の予備費を見込む。一般公開に必要なインストーラー、署名、公証、自動更新までPhase 1へ含める場合は、さらに**0.5〜1.0人月**程度を追加する。

## 6. 推奨する開始方法

最初の2週間を基盤・技術スパイクに充て、次を実装・計測する。

1. Cargo workspaceと依存方向
2. `PixelGrid`と基本編集コマンド
3. egui上の整数座標入力とNearest Neighbor表示
4. Pencil／Eraser、1ジェスチャー1 Undo
5. 拡大キャンバスと同時更新される1×プレビュー
6. 小さなプロジェクトの保存→読込往復

このスパイクを約0.5人月で実施し、実測した開発速度、描画遅延、OS差異を基に残工数を再見積もりする。Phase 1全体を一括で確定するよりも、予算と納期の誤差を抑えやすい。

## 7. 見積もり精度

現段階の見積もりは仕様・設計文書を基にした概算であり、精度はおおむね**−20%〜＋40%**とする。特に次の条件は上振れ要因になる。

- Rust／eguiの経験が少ない担当者による実装
- 初回から商用品質のUIデザインやアクセシビリティを求める場合
- 破損ファイル対策、クラッシュ復旧、クロスプラットフォーム配布を高い水準で仕上げる場合
- ユーザーテストで練習フローの大幅な作り直しが発生する場合
- Phase 1中にレイヤー、選択移動、アニメーション等を追加する場合

仕様追加はPhase 1へ混在させず、MVPの仮説検証後にPhase 2以降として再評価する。
