# ドット絵スキル向上ツール仕様

## 1. 製品概要

### 仮称

**Dotted Training Studio**

### 目的

小さなドット絵を完成させるだけでなく、観察、再現、省略、比較、振り返りを短い周期で繰り返し、ユーザーが自分の弱点を理解して次の1枚へ反映できるようにする。

製品の価値は高機能な画像編集ではなく、次の学習ループを中断なく回せることにある。

```text
課題と制約を決める
→ 参照を観察して特徴を言語化する
→ 模写する
→ 参照を隠して記憶から描く
→ 学んだ特徴を別案へ応用する
→ 等倍・シルエット・明度・背景で検証する
→ 不要なドットを削る
→ 各版を比較する
→ 次回試すことを1つ記録する
```

### 成功の定義

- 初回利用者が説明なしで16×16・4色の練習を開始し、30分以内に比較と振り返りまで完了できる。
- 練習終了時に「何が良くなったか」「次に何を試すか」を本人が説明できる。
- 同じ題材の複数版を、ピクセルを失わず後日描き直して比較できる。
- 編集中も等倍での視認性を常に判断できる。

完成枚数、連続利用日数、診断警告の少なさだけを上達指標にはしない。主指標は、意図を持って完成・比較・振り返りまで行った練習セッション数と、過去に設定した改善点を次回試せた割合とする。

## 2. 対象ユーザー

### 主対象

- ドット絵を始めたばかりで、何をどう練習すればよいか分からない人
- 一般的なペイントソフトでは機能が多すぎて、練習の焦点を失いやすい人
- ゲーム用の16×16～32×32素材を、等倍で読みやすく作りたい人

### 副対象

- 色、輪郭、アニメーションなど特定の弱点を反復練習したい中級者
- 同じ題材の変化や過去作品との差を記録したい人

### 対象外

- 大判イラストの制作、写真加工、ベクター変換を主目的とする利用
- AIや自動補正に完成品を作らせる利用
- 1bit画像だけを対象とする専用ツール

## 3. 設計原則

1. **制約を見せる**：サイズ、色数、時間、練習テーマを常時確認できるようにする。
2. **等倍を正とする**：拡大編集と同時に1×プレビューを表示し、評価は実利用時の見え方で行う。
3. **答えを奪わない**：問題箇所は示しても、無断でピクセルを修正しない。
4. **比較可能にする**：模写、記憶描き、応用、修正版を別成果物として保存する。
5. **1回を完結させる**：短時間でも必ず制作、検証、振り返りまで到達できる。
6. **評価に順序を持たせる**：視認性、シルエット、明度差、ピクセル配置、アニメーション、色、細部の順に案内する。
7. **練習と作品を分ける**：参照や診断表示は制作ピクセルへ混入させない。
8. **行動から次を決める**：統計や実績は上手さの序列化ではなく、未経験の練習法を案内し、次の課題を選びやすくするために使う。

本書の4～10章は将来を含む製品像を示す。Phase 1の範囲は11章、実装契約は[プログラム設計](Dotted%20Training%20Studioプログラム設計.md)を正とする。MVPでは応用、削減、過去版の再編集、自由練習、統計・提案・実績、重ね合わせ、高度診断は提供しない。

## 4. 中核となる練習モード

### 4.1 観察・記憶・応用セッション

本製品の最優先モード。1つのセッションを次の段階で構成する。

| 段階 | ユーザーの行動 | ツールの支援 | 保存物 |
| --- | --- | --- | --- |
| 課題設定 | 題材、サイズ、色数、時間を選ぶ | 前回の改善点を基にプリセットを提案 | 課題と制約 |
| 観察 | 外形、明暗、識別点を各1つ書く | 参照表示、観察用タイマー | 観察メモ |
| 模写 | 参照を見ながら描く | 拡大編集、等倍表示、色数表示 | `copy`版 |
| 記憶描き | 参照を隠して描き直す | 参照を完全に隠し、別キャンバスを作成 | `memory`版 |
| 応用 | ポーズ、属性、向き等を変えて描く | 変更条件を1つ提示 | `variation`版 |
| 検証 | シルエット、明度、背景、左右反転で見る | 表示だけを切り替える診断パネル | 検証メモ |
| 削減 | 1ドットずつ消す前後を比べる | 一時プレビュー、採用／取消 | 独立した`cleanup`版 |
| 比較 | 参照、各版、過去版を並べる | 横並び、点滅、重ね合わせ | 比較対象 |
| 振り返り | 狙い、できたこと、次回の1点を書く | 3つの短い入力欄 | 振り返り |

段階の成果物は閲覧できるが、後段の版で前段を上書きしない。確定版から新しい作業版を作る再編集はPhase 2とし、MVPの「戻る」は閲覧専用とする。Memory中の過去版閲覧も参照再表示の明示操作が必要。途中終了は保存完了を待って再開可能にする。

### 4.2 サイズ再解釈セッション

同じ題材を32×32、16×16、8×8など複数サイズで個別に手描きし、何を残して何を捨てるかを学ぶ。自動縮小結果は正解として提示しない。

- 標準順序は `16×16 → 8×8 → 32×32` とする。基本形、省略、情報追加の差を理解しやすいため。
- 各サイズは独立したピクセルデータを持つ。
- 比較画面では全サイズを同じ表示面積ではなく、1×と共通拡大倍率の両方で並べる。
- 終了時に「全サイズで残した特徴」「8×8で捨てた情報」を記録する。

### 4.3 短時間ドリル

- 8×8または16×16、2～4色、3～5分を標準とする。
- 題材カテゴリは道具、食べ物、動物、顔、記号、単純形状とする。
- 狙いは完成度ではなく、シルエットと輪郭リズムに絞る。
- ランダム出題だけでなく、苦手項目から選べるようにする。

### 4.4 アニメーション練習（MVP後）

- 2、4、6、8フレームから選ぶ。
- キーポーズを先に確定し、その後に中間フレームを追加する。
- フレーム複製、表示時間、タグ、オニオンスキン、ループ、実速度1×再生を提供する。
- 体積、接地点、ポーズ差、ループ接続を振り返り項目にする。

### 4.5 シルエット集中セッション（MVP後）

色や内部線を使わず、対象を識別させる特徴、重心、ポーズ、情報削減を鍛える。

1. 題材と条件を確認する。
2. 参照がある場合は10秒間観察し、識別に必要な特徴を3つ記録する。
3. 1色、8×8～16×16、3～5分で描く。
4. 完成結果を1×で1秒だけ表示し、その後に通常表示へ戻す。
5. 「何として読めるか」「残した特徴」「不要だった突起」を自己評価する。

段階的な課題として、自由シルエット、短時間記憶、ポーズ指定、類似対象の描き分け、サイズ再解釈、使用ピクセルの10～30%削減を用意する。猫／犬／狐、剣士／魔法使い／弓使いのような類似対象は、色に頼らず識別点を設計する練習として扱う。

一瞬認識テストは正誤をツールが推測せず、ユーザーまたはテスト協力者が回答したラベルと表示時間を記録する。将来、他者評価を導入する場合も、描き手へ人格的・総合的な点数を付けず、題材認識とポーズ認識を分けて扱う。

### 4.6 パレット観察セッション（MVP後）

単色のRGB値を暗記するのではなく、暗部、影、ベース、明部など、色同士の役割と距離を見抜く力を鍛える。

```text
単色を目で再現
→ 3～8色のパレットを再現
→ 参照を隠してパレットを再現
→ 主要色だけを抽出
→ 再現したパレットで作品を描く
```

- スポイトは回答確定まで無効にする。
- 結果は色ごとの一致度だけでなく、明度ステップ、彩度変化、色相の移動方向を分けて示す。
- 「全体に明るく見積もる」「影とベースの明度差が小さい」など、再現傾向を説明する。
- 個々の色が多少ずれても色間関係が保たれている場合は、その点を明示する。
- 色差計算は知覚色空間を用いるが、単一の総合点だけで成功・失敗を決めない。
- 相対色課題では「基準色より暗く、少し青寄り、低彩度」などの条件から色を作る。

## 5. 画面仕様

### 5.1 ホーム

- 「今日の練習を始める」を最も強い操作にする。
- 前回の「次に直すこと」と、それに対応する推奨課題を表示する。
- 30分基本、15分短縮、自由練習から選択できる。
- 履歴は連続日数より、直近の練習テーマと描き直し時期を優先して表示する。

### 5.2 課題設定

- 練習モード、題材、キャンバスサイズ、色数上限、制限時間、背景を設定する。
- 初級プリセットは16×16、4色、30分を既定とする。
- 制約ごとに「何を鍛える設定か」を1行で説明する。
- 参照画像には出典、作者、利用条件、URLを任意で記録できる。模写成果物は既定で「個人練習」と表示する。

### 5.3 練習ワークスペース

```text
┌──────────────────────────────────────────────────────────┐
│ 課題 / 現在段階 / 残り時間       色 4/4       保存状態    │
├──────────────┬──────────────────────────┬───────────────┤
│ 参照・指示   │                          │ 1× Preview   │
│ 観察メモ     │       拡大キャンバス     │ 背景切替      │
│              │                          │ 診断          │
├──────────────┴──────────────────────────┴───────────────┤
│ Palette │ Pencil Eraser Fill Eyedropper │ Undo Redo    │
├──────────────────────────────────────────────────────────┤
│ 戻る                       現在段階を完了して次へ         │
└──────────────────────────────────────────────────────────┘
```

- 現在の練習段階と次の行動を常に1つ明示する。
- 参照は模写終了後に隠れ、明示操作なしに再表示しない。再表示した場合は記録するが、罰や失敗扱いにはしない。
- タイマー終了後も描画は禁止しない。「時間を超えて続ける」「現在版を確定する」を選べる。
- 1×プレビューは常時表示し、作品1画素＝画面1物理ピクセルを保つ。パネルの余白は縮めても作品自体は縮小しない。白、黒、灰、透明チェッカー、課題背景を切り替えられる。MVPの課題背景はこれらのプリセットから選ぶ。

### 5.4 検証・クリーンアップ

次の表示を同じパネルから切り替える。

- シルエット：不透明ピクセルを単色化する。
- グレースケール：知覚的な明度差を確認する。
- 左右／上下反転：表示のみを反転し、データ変更の確定操作は提供しない。MVPは左右のみで、反転表示中の描画は無効にする。
- 背景：白、黒、灰、透明、市松、登録したゲーム背景。
- 色数：使用色数／上限、未使用パレット色、似た色の候補。
- ピクセル配置：孤立ピクセル、急な輪郭段差、過密なディザの候補。

警告には必ず「なぜ確認するか」と対象箇所を示す。閾値に絶対的な正解がない診断は「誤り」ではなく「確認候補」と表記する。

クリーンアップでは、1操作ごとに削除前後を点滅比較できる。削除を確定するまで編集データへ反映せず、確定後は1回のUndoで戻せる。

### 5.5 比較・振り返り

- 参照、模写、記憶描き、応用、クリーンアップ後、過去版から2～4枚を選ぶ。
- 横並び、A/B点滅、透明度スライダーによる重ね合わせを提供する。
- 異なるサイズ同士の重ね合わせは禁止し、1×横並びまたはNearest Neighborによる共通整数倍率で比較する。
- ピクセル差分は表示できるが、参照との差の小ささを点数化しない。模写の完全一致が構造理解や良い省略を意味するとは限らないため。
- 振り返りは「今回の狙い」「できたこと」「次に1つ試すこと」の3項目を必須とし、各140文字以内にする。

### 5.6 履歴

- 日付、題材、サイズ、色数、練習モード、テーマで絞り込める。
- 同じ題材の版を時系列で並べ、再練習を開始できる。
- 週単位でシルエット、色、明暗、ピクセル配置、アニメーション等の実施回数を表示する。
- ストリークを主役にせず、「未再挑戦の改善点」と「描き直す候補」を表示する。

#### 学習統計

統計は「上手さ」を一つの数値にせず、行動、制約、本人の変化を事実として表示する。

- 練習時間、完了セッション数、完成作品数
- 模写、記憶描き、応用、シルエット、パレット、アニメーションの実施数
- 8×8、16×16、32×32等のサイズ分布
- 題材カテゴリと練習テーマの分布
- 使用色数、制限内で完成した割合
- 作品あたりの制作時間、クリーンアップ前後の不透明ピクセル数
- 自己評価で選んだ改善テーマと、その後の再挑戦回数
- パレット練習における明度、彩度、色相の再現傾向

Undo回数や削除ピクセル数は操作事実として保存しても、少ないほど上手いとは解釈しない。期間比較では「制作時間18分→11分」「記憶描き2回→14回」のように観測値を示し、能力スコアへ合成しない。

#### 次の課題の提案

- 前回の「次に1つ試すこと」を最優先候補にする。
- 直近4週間で未実施または少ないテーマを補完候補として示す。
- 同じ弱点に対して、より小さいサイズ、少ない色、短い時間など一度に1つだけ制約を変える。
- 提案理由を「最近4週間でアニメーション練習が0回」のように表示する。
- 提案は拒否、延期、別課題への変更ができ、強制しない。

#### カリキュラム型実績

実績は継続日数を競わせる報酬ではなく、良い練習方法を一度体験してもらう任意の導線とする。

| 実績例 | 条件 | 教える行動 |
| --- | --- | --- |
| はじめの1ドット | 初めてセッションを完了 | 制作から振り返りまで一周する |
| Four Colors | 4色以内で完成 | 色を増やす前に役割を考える |
| Memory Painter | 記憶描きを完成 | 見た形を構造として保持する |
| Three Sizes | 同じ題材を3サイズで手描き | 特徴を残して情報を削る |
| Less is More | 削減前後を比較して採用 | 1ドットの必要性を判断する |
| Key Poses First | キーポーズ確定後に中割りを追加 | ポーズ→タイミング→中割りを守る |

同じ実績を量だけ増やすための反復、長時間利用、診断警告ゼロを条件にしない。解除のために作品を不自然に変えないよう、削除数などの閾値より「比較して意図を記録したか」を条件にする。

## 6. 編集機能

### MVP必須

- Pencil：1ピクセル幅、整数座標、アンチエイリアスなし
- Eraser：透明色へ置換
- Fill：現在のレイヤー／フレーム内で連結領域を塗る
- Eyedropper：合成表示ではなく、選択中レイヤーの実色を標準取得
- Undo／Redo：1回のドラッグ、塗りつぶし、パレット変更等を1トランザクションにする
- ズーム／パン：Nearest Neighbor、キャンバス座標とのずれなし
- グリッド：非表示、1×1、8×8、16×16
- パレット：alpha>0の2～8色を登録し、消去を別に提供する。使用数を常時表示する。半透明RGBAは保持し、透明は使用色数に含めない

### MVP後

- Line、矩形選択、移動
- 簡易レイヤー（sprite、guide。参照は編集レイヤーと分離）
- 対称描画
- 複数フレーム、オニオンスキン
- タイル繰り返し表示

ブラシ、ぼかし、フィルター、レイヤー効果、任意角度回転、補間を伴う拡縮は当面実装しない。

## 7. パレットと診断仕様

- 色数は透明色を除いた、現在の比較対象に実際に使われているRGBA色の数とする。
- 上限超過時も描画可能とし、色数表示と対象色を警告状態にする。
- 似た色は知覚色空間での距離を用いて候補を示す。閾値は設定可能にし、統合前に置換対象と結果をプレビューする。
- グレースケール表示は元データを変更しない。
- 孤立ピクセル等の診断は透明／不透明だけでなく同色クラスタを考慮し、意図的な目や星などもあるため自動削除しない。
- 診断結果の個数を品質スコアへ変換しない。

## 8. データモデル

UI状態と保存対象を分離する。

```text
Project
├─ id, title, created_at, updated_at
├─ artworks[]
├─ references[]
└─ sessions[]

Artwork
├─ id, role, status(Draft|Finalized), source_artwork_id
└─ document(size, palette, layers, frames, cels)

PracticeSession
├─ id, exercise, status, stage, subject, reference_id
├─ constraints(size, initial_palette, color_limit, time_limit_ms, background)
├─ observations(outline, value, identifying_feature)
├─ artifacts(stage, artwork_id)[]
├─ reference_visibility, elapsed_ms, events[]
├─ validation_note, reflection_draft
└─ reflection(goal, success, next_try)

Reference
├─ id, image
└─ source_title, creator, source_url, usage_note

TransientUiState
└─ zoom, pan, active_tool, selected_color, selection, dialogs,
   preview_mode, reference_display_transform, comparison_phase
```

- ピクセルはレイヤー／フレームごとの整数グリッドを正とする。完全透明RGBAは(0,0,0,0)に正規化し、それ以外のRGBAを正確に保持する。
- パレットはArtworkごとに所有し、選択色はUI、色数上限はConstraintsへ分離する。パレット変更は既存RGBAを置換せず、確定版のパレットへ影響しない。
- MVPのProjectは1セッション、参照1枚、Copy／Memory各最大1枚。各Artworkは1レイヤー・1フレーム・1Cel。タグ、実績、診断スナップショットは後続フェーズで必要になってから追加する。
- Copy確定、別IDのMemory白紙生成、リンク登録、参照非表示、イベント記録を1つの原子的変更にする。Memory構築APIへCopy画素を渡さず、独立した透明グリッドと空のUndo／Redoを作る。Copyのサムネイル・比較経路も明示再表示まで隠す。
- 確定版は画素とパレットを含め不変とする。Undo／Redoは現在Draftの画素とパレットに限定し、段階遷移や練習記録を巻き戻さない。失敗・キャンセル・正味無変更で履歴を壊さない。
- 自動保存は編集・メモ確定後の1秒アイドルまたは5秒の未保存継続時に要求し、段階遷移時は即時要求する。ドラッグ途中は保存せず、最後の編集確定境界を使う。クラッシュ時は最後に書込み完了した復旧スナップショットまで復元し、完了前の直近操作は保証しない。
- 統計用イベントは段階確定時の観測値と参照再表示等に限定する。現在状態が再開の正本で、ポインター移動の生入力や汎用イベントソーシングは保存しない。
- 観察・出典・検証メモ・振り返り草稿も入力確定時に保存対象へ反映する。振り返り確定はtrim後非空の3項目、各140 Unicodeスカラー値以内。IME変換途中はUI状態とする。

## 9. 保存・入出力

- 編集用`.dotted` v1はZIP内のJSONメタデータとCelごとの原寸RGBA8 PNG、埋込み参照PNGを保持する。ピクセル、透明度、作品ごとのパレット、レイヤー／フレーム順、固定フレーム時間、参照情報、セッション、草稿・振り返りを往復保持する。タグはアニメーション導入時に追加する。
- 静止画は原寸透過PNGを必須出力とする。
- 2×、4×、8×の確認用PNGは整数Nearest Neighborで生成する。
- 参照画像やガイド、診断オーバーレイは作品PNGへ含めない。
- アニメーション対応後はGIFまたはAPNG、およびスプライトシート＋メタデータを出力する。
- 保存→読込で正規化済みの全ピクセル、色、透明度、順序、フレーム時間が一致しなければならない。
- 保存version、ID参照、段階と成果物状態、ZIPパス、重複エントリー、サイズ上限、PNG寸法・形式・ハッシュを検証し、不整合を黙って修復しない。詳細上限はプログラム設計8.1に従う。
- 保存は不変snapshotを単一I/Oワーカーで直列処理し、古い完了通知で現在の変更を保存済みにしない。明示保存と復旧保存の状態は別に管理する。失敗時は旧ファイルを保持し、再試行・別名保存を提供する。
- 参照インポートは静止PNG／JPEGに限定し、向き適用・RGBA8化・完全透明色の正規化後に埋め込む。アニメーションと16bitは説明付きで拒否し、自動縮小・減色しない。作品PNGの編集用インポートはMVP外。
- SQLiteは再構築可能な履歴索引であり、保存ファイルが正本。通常保存成功後だけ更新し、索引失敗で作品保存を失敗扱いにしない。

## 11. MVP

### MVPで検証する仮説

「参照を見て描くだけでなく、隠して白紙から再現し、複数版を比較して次の改善点を残す流れが、初心者に明確な学びを生む」

### MVP範囲

1. 16×16／32×32の新規課題
2. 2～8色パレットと色数上限
3. Pencil、Eraser、Fill、Eyedropper、Undo／Redo
4. 拡大キャンバスと常時1×プレビュー
5. 参照画像の読込、出典記録、表示／非表示
6. 観察メモ
7. 模写→参照を隠す→白紙の記憶描き
8. シルエット、グレースケール、背景、左右反転の表示診断
9. 模写／記憶描きの横並び・点滅比較
10. 3項目の振り返り
11. セッション自動保存、再開、履歴
12. 原寸／整数倍PNG出力

MVPのホームは固定の16×16・4色・30分推奨プリセットと同梱の出典付き参照から「練習を始める」→観察画面の1操作で開始できる。サイズ・パレット・参照変更は任意の設定経路とし、参照読込ダイアログを初回開始の必須条件にしない。同梱参照もProjectへ埋め込む。

履歴は保存したセッションの日付・題材・段階・完了状態の一覧と未完了再開まで。高度な絞り込み、過去版比較、再練習提案はPhase 2へ置く。MVP比較は同じセッションのCopyとMemoryの横並び／500 msのA/B点滅、タイマーは前景練習時間のみを加算する。原寸表示、背景、グリッド、ズーム、パンはUI操作で保存内容を変更しない。

サイズ再解釈はMVP直後の最優先機能とする。アニメーション、ゲーム画面プレビュー、タイル、似た色や孤立ピクセルの高度診断は、その後に追加する。

### MVP受け入れ条件

識別子は[プログラム設計10.5の検証対応表](Dotted%20Training%20Studioプログラム設計.md#105-受け入れ条件とテストの対応)と共通とする。

| ID | 受け入れ条件 |
| --- | --- |

| AC-02 | Copy確定と同時にMemoryが別ID・独立した全透明画素・空履歴で作られ、明示再表示までCopyと参照の全表示経路が隠れる |
| AC-03 | 模写、記憶描き、参照・出典、メモ・草稿、段階、再表示状態、振り返りが保存後の再起動で復元される |
| AC-04 | 描画中も拡大と常時1×プレビューが同じ表示フレームの画素を表示し、1×は物理ピクセル等倍を維持する |
| AC-05 | 16×16／32×32の端・四隅で整数ズーム、パン、DPIにかかわらず入力座標が一致し、枠外・高速入力・フォーカス喪失でも不要な画素変更がない |

| AC-09 | 原寸／2／4／8倍PNGを再デコードすると正規化済みRGBAと透明度が一致する |
| AC-10 | 未完了セッションは最後に書込み完了した復旧snapshotから再開できる。保存中の編集・Undo・別名保存・別Project読込でも古い通知が現在状態を壊さない |
| AC-11 | 破損・上限超過・未対応.dottedを既存編集中データを保持して拒否し、保存失敗で旧ファイルを失わない |
| AC-12 | 観察3項目から比較・振り返りまで許可された順に進み、タイマー超過や参照再表示を失敗扱いしない。履歴から未完了再開できる |

## 12. 開発フェーズ

### Phase 1：中核ループ

MVP範囲を完成させ、5～10人の初心者に30分セッションを実施してもらう。開始までの迷い、記憶描きの理解、比較後に具体的な改善点を書けたかを観察する。

### Phase 2：再解釈と描き直し

- 16→8→32のサイズ再解釈
- 同題材の再練習提案
- クリーンアップ比較
- 似た色、孤立ピクセル、輪郭リズムの確認候補
- 週次の練習テーマ可視化
- シルエット集中セッションと1秒認識テスト
- パレット観察と色間関係のフィードバック
- 行動統計、理由付き課題提案、カリキュラム型実績

### Phase 3：アニメーション

- フレーム、時間、タグ、オニオンスキン
- キーポーズ優先フロー
- 実速度・等倍プレビュー
- GIF／APNG／スプライトシート出力

### Phase 4：利用文脈

- RPG、Platformer、Top-down等のゲーム画面テンプレート
- タイル繰り返し表示
- 素材セットと共有パレット
- 背景、他素材、UIを含む視認性比較

## 13. 検証計画

### コアの自動テスト

- 各ツールの固定入力に対するピクセル配列
- キャンバス端、ドラッグ補間、塗りつぶし境界
- Undo／Redoのトランザクション境界
- パレット変更、透明色、色数集計
- 各診断が元データを変更しないこと
- プロジェクト保存→読込の完全往復
- PNGのピクセル完全一致

### ユーザビリティ検証

- 説明なしで今日の練習を開始できるか
- 模写と記憶描きが別成果物だと理解できるか
- 等倍プレビューを実際に判断へ使うか
- 比較後に具体的な「次に1つ試すこと」を書けるか
- 警告を正解判定と誤解しないか

### 見送る評価

- 参照との画素一致率による採点
- AIによる美しさの総合点
- 利用日数だけを促すログイン報酬
- 診断警告をゼロにすることの強制
- Undo回数、制作速度、削除量を上手さとして順位付けすること

これらは省略や意図の質を測れず、正解への迎合や無意味な継続を促すためである。

## 14. 技術方針

- 初期実装はRustのUI非依存コアとデスクトップUIを分離する。
- `pixel_core`はキャンバス、レイヤー、フレーム、パレット、編集コマンド、履歴を担当する。
- `training`はProject／Artwork、課題、制約、段階遷移、タイマー規則、比較対象、振り返りを担当する。比較描画・時計取得・点滅位相はdesktopに置く。統計、提案、実績はPhase 2で練習イベントから導出する。
- `project_io`はプロジェクト保存、参照読込、PNG出力、復旧ファイル、SQLite索引を担当する。`desktop -> {training, pixel_core, project_io}`、`training -> pixel_core`、`project_io -> {training, pixel_core}`とし逆依存は禁止する。
- UIはコアへコマンドを送り、ピクセル編集やセッション規則を直接保持しない。
- GUI主体のMVPでは`eframe/egui`が適する。ゲーム画面プレビューが中心機能になった場合のみ、その部分へのBevy等の採用を再評価する。

## 15. 未決定事項

実装開始前またはプロトタイプ検証で次を決める。

- Windows／macOSの最低対応バージョンと実機表示・入力検証
- eguiと時刻／画像／ZIPライブラリの固定バージョン、保存先のOS別管理パス
- 将来のWeb／タブレット対応（MVP外）
- 似た色、孤立ピクセル、輪郭リズムの既定閾値
- 将来の履歴同期（MVPはローカル専用）
- 一瞬認識テストを本人の自己回答だけにするか、任意の第三者テストも扱うか

MVPはWindows／macOSデスクトップ、ローカル完結、参照埋め込み、ZIP形式.dotted、SQLite索引に固定する。ネットワークやアカウント登録なしに中核練習を完了できることを優先する。

汎用の大きなブラシキャンバスからドットへ変換する「Silhouette → Pixel」は、観察から単純化へ進む学習法として有望だが、自由描画エンジンを持つ一般的な造形ツールへ範囲が広がる。初期製品では1色のピクセルシルエットと手描きのサイズ再解釈で仮説を検証し、それで不足することが確認された場合に別モードとして再評価する。
